# Contributing

1. Read the README, roadmap and upstream maintenance policy.
2. Check existing issues before starting work.
3. Keep changes focused and use a feature branch.
4. Add tests for behaviour changes and update docs/diagrams when contracts change.
5. Clearly label assumptions about undocumented NotebookLM service behaviour.
6. Do not include credentials, cookies, real notebook content or personal data in fixtures.
7. Open a PR with motivation, implementation notes, tests, limitations and related issue links.

Prefer changes that are useful upstream as well as locally. Where appropriate, submit a separate contribution to the original project rather than assuming fork-specific changes belong upstream.
